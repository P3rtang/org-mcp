* Error conventions (non-negotiable)
  :PROPERTIES:
  :ID: 41497269
  :END:
  - [ ] *500-class (top-level err)* — reserved for org-mcp/server failures: context lost, file unreadable, parse panic. Bubble up as =error= from the tool callback. Not for recoverable tool mistakes
  - [ ] *400-class (response items)* — every tool-level failure (bad op, not found, duplicate, out of range, name taken) is NOT =err=; appended into the response array so batched ops stay decodable. Convention bullet =48779879.b6= in =docs/index.org=
  - [ ] *Generic structural checks stay centralized* — =Header.AddChildren= owns the parent/child + duplicate-uid contract; feature paths (create/add) do NOT re-implement it. They may pre-resolve parameters to produce *feature-specific* messages alongside the structural fail
  - [ ] *Templates live in =orgmcp/types/errors.go=* — one string constant per error, prefixed (see catalog). Callers =fmt.Errorf(TEMPLATE, ...)= with values only — no ad-hoc error text

* Message template guidelines
  :PROPERTIES:
  :ID: 1418073
  :END:
  - [ ] *Prefix = code = detail* — today: =ERROR | [%T]: <state>. <remedy>= via =types/errors.go=. Proposal: keep the prefix, insert a stable short code token between — =ERROR | TAKEN_NAME.[%T]: ...= — codes (=ROW_OUT_OF_RANGE=, =COLUMN_OUT_OF_RANGE= exist already) let tests and agents classify errors cheaply
  - [ ] *Three-act message* — (1) what failed / what was asked, (2) actual state (uids, names, indices), (3) exact remedy composed of real op names. Remedy parameters must be copy-pasteable into the next tool call verbatim. Never generic verbs ( modify ) and never call a =name= a =UID=
  - [ ] *No anonymous referents* — “This item” style is being phased out; name the entity kind + uid. When the fix is “use the parent”, include the parent UID verbatim so the agent self-heals in one step (create requires a header uid; `X.Y` resolves to a table — use its parent header `X` instead)
