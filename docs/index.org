** tooling feedback log (org-mcp quirks observed while using it) :issue:ux:
   :PROPERTIES:
   :ID: 48779879
   :END:
   - [ ] *Empty org file → request timeout* — any org-mcp call against a 0-line file times out server-side instead of returning an empty structure or a clean error. Tracked = fix in =docs/tables/issue-31.org= (=31j10=)
   - [ ] *EXAMPLE blocks flattened* — =#+BEGIN_EXAMPLE= is not parsed as a codeblock entity; in =issue-31.org= each line of the block became its own plain text item (=31l12.t1= .. =31l12.t10=) while =#+BEGIN_SRC= blocks are properly grouped as single codeblock items. Cost: inflated UID space + block identity lost on re-render. Suggest: treat EXAMPLE like SRC for parsing
   - [ ] *Bullet LEVEL is ambiguous* — nested bullets report the same LEVEL as their parent bullet (=31d4.b2.b0= shows LEVEL 2, same as =31d4.b2=), likely mirroring the owning header's level; make it nesting depth or rename the column
   - [ ] *Non-standard status keywords mangle headers* — a hand-written line like =* DEADLINE <2026-11-01> DONE Issue 31 ...= parsed to status NEXT with garbled content; maybe warn/flag on unknown keywords or try TODO-kw = date extraction
   - [ ] *manage_header parent "" unhelpful* — passing =parent: ""= to add a root header errors =Parent UID not found= with no hint; either accept "" (or "0") as root or have the error message list valid values
   - [ ] *New table creation impossible* (the big one, seen live): =manage_table= has no create op; calling =add= against a header silently no-ops with an empty ={}= response — tracked as =31b2= with TDD spec
   - [ ] *Error convention (from user, 2026-10-10)* — top-level =err= is reserved for org-mcp / server failures (500-class). Tool-level \"400-class\" errors (bad op, not found, duplicate, out of range) are NOT returned as err — they are passed as response items, e.g. =Header with UID `X` already contains a child with UID `Y`...= or =This item cannot have children.= Test helpers must match expected errors against response items (strings or error objects); see =runManageTableTest= convention
   - [ ] *opencode client harness mangles escaped quotes* — proven in-process: client-identical JSON bytes pass clean through json.Unmarshal + manage_table callback end-to-end on disk. Corruption originates in opencode between the model args and the server: escaped quotes in bullet content and table cells get dropped or reinterpreted (backtick becomes =]=). The MCP client is the buggy layer, not the server. Workaround: smart quotes in content
