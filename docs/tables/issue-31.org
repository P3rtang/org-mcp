** TODO fix: tool output is unlabeled, ambiguous, and manufactures duplicate rows :table:ux:output:
   :PROPERTIES:
   :ID: 31l12
   :END:
   The biggest day-to-day friction: the response format. Live repro with one batched call of 3 =add= ops on a 1-row-header table produced:
   #+BEGIN_EXAMPLE
   Name,Role
   Alice,Dev
   Name,Role
   Alice,Dev
   Bob,QA
   Name,Role
   Bob,QA
   Carol,Ops
   #+END_EXAMPLE
   - [ ] **Duplicate rows in output** — each op returns a neighborhood snapshot ( =GetRange(row-1, row+2)= = =tools/manage_table_tool.go:239= , =:258= Saints, =:276= ). Ranges overlap between batched ops, so =Alice= appears in chunks 1 =AND= 2, =Bob= in 2 =AND= 3. The disk table is correct, but the response /looks dt-like duplicatd data/ — models routinely misread this and act on phantom dupes
   - [ ] **Stale state in output** — chunk 1 shows state /after op 1/, which op 2 and 3 have since invalidated. The model gets three /different/ table states in one response with nothing saying which is current
   - [ ] **No op/result association** — response items are unlabeled positional elements in a flat =[]any=: an error / a raw message / a CSV string, whichever that op happened to produce ( =:348-371= ). With 5 ops and 2 errors, the model must guess which item maps to which op
   - [ ] **Errors interleaved as raw objects** — =resp = append(resp, res.err)= puts Go error values right next to CSV strings, no marker
   - [ ] **Inconsistent shapes per op** — row ops return CSV neighborhoods; column ops return prose ( =COLUMN_ADDED= etc.); no-ops return nothing and the whole response degrades to ={}= — impossible to distinguish "success, nothing to say" from "failed, nothing happened"
   - [ ] **No final-state view** — to see the resulting table the model usually needs a follow-up =query_table= call; if a batch ends in partial failure, you cannot tell what actually persisted
   - [ ] **Partial success is invisible** — batch continues past errors and =WriteOrgFileToDisk= runs unconditionally ( =:373= ); success/failure per item is indistinguishable in the unlabeled stream
   Proposed response contract: one entry per op, each ={"op": <index or tag>, "status": "ok|error", "error": "...", "affected": {...}}= + optional single =final_table= CSV at the end (the current state, on request). Kill the overlapping neighborhood windows.
